# План тестирования

## Unit
- Валидные/невалидные статусы задач.
- Валидные/невалидные приоритеты.
- Хеширование и проверка пароля; разный salt должен давать разные хеши.
- Разбор JWT с истёкшим токеном, неверной подписью и неверным типом.

## Интеграционные сценарии, которые необходимо выполнить перед защитой
1. Регистрация, вход, получение профиля и logout с тестовой PostgreSQL.
2. Запрет чтения проекта пользователем, не входящим в project_members.
3. CRUD задачи, серверная фильтрация/пагинация и история статусов.
4. RBAC: participant получает 403 на admin endpoints, admin может менять роль.
5. Загрузка разрешённого файла и отказ для неподдерживаемого расширения/слишком большого файла.

## Frontend
- Проверка пяти колонок канбана.
- Проверка отображаемых названий статусов.
- Проверка уникальности идентификаторов статусов.

## E2E
Рекомендуемый сценарий Playwright: вход → открыть проект → создать задачу → переместить её в «В работе» → проверить обновлённый статус.

## Покрытие
Снять фактический отчёт после запуска тестов. Не указывать покрытие ≥60%, пока его не подтверждает инструмент покрытия.
